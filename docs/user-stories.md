사용자로서, 데이터를 안전하게 다루기 위해 같은 이름 대상이 있을 때 명시적으로 선택하고 싶다.
- [ ] 같은 이름 대상이 있으면 **명시적 확인 없이 임의 덮어쓰기가 일어나지 않는다**
- [ ] 충돌 다이얼로그에서 **덮어쓰기 / 건너뛰기 / 둘 다 유지** 중 선택할 수 있다
- [ ] **둘 다 유지** 선택 시 새 항목이 "이름 (n)"으로 명명되어 양쪽이 보존된다
- [ ] 같은 이름 **폴더**는 삭제·교체가 아니라 **병합**되며, 내부 동일명 파일만 다시 충돌 판정된다
- [ ] **모두 적용** 체크 시 이후 동일 유형 충돌에 같은 선택이 일괄 적용되어 다이얼로그가 재표시되지 않는다
- [ ] **읽기전용** 대상 덮어쓰기는 추가 확인 후 진행, 거부 시 건너뛴다
- [ ] **사용 중 / 권한 없는** 대상은 사유와 함께 자동 건너뛰고, 작업 종료 후 **실패 항목·사유 목록**이 요약된다
- [ ] 충돌 다이얼로그에 양쪽 항목의 **크기·수정일**이 비교 가능하게 표시된다

### US-7.1 상단 아이콘바로 빠르게 실행 — S · 규모 M · ✅ 완료
사용자로서, 자주 쓰는 기능을 마우스로 빠르게 실행하기 위해 상단 아이콘 버튼바를 쓰고 싶다.
- [x] 탭바 아래에 레이아웃/뷰·파일 작업·탐색·도구 4개 그룹이 구분선으로 나뉘어 표시된다(`iconBarItems.ts` 4그룹)
- [x] 각 버튼 클릭이 키보드 단축키와 동일한 commandId를 활성 패널에 실행한다(execCommand 수렴)
- [x] 컨텍스트상 불가능한 동작의 버튼은 비활성(흐림)되고 클릭해도 동작하지 않는다(activeWhen)
- [x] 토글형 버튼(사이드바·미리보기·테마·분할 모드·보기 모드)이 현재 상태를 시각적으로 반영한다(`aria-pressed`)
- [x] 버튼 툴팁에 동작명과 해당 단축키가 표시된다
- [x] 테마 토글 버튼이 라이트↔다크를 즉시 전환한다(`theme.toggle`→`toggleThemeMode`)

### US-7.2 사이드바를 접어 화면 넓게 쓰기 — S · 규모 S · ✅ 완료 (※ 실제 토글은 런타임 스모크 권장)
사용자로서, 패널을 넓게 쓰기 위해 좌측 사이드바를 접고 펴고 싶다.
- [x] `Ctrl+B` 또는 아이콘바 버튼으로 사이드바가 표시↔숨김 전환된다(`sidebar.toggle`→`toggleSidebar`)

- [x] 토글 상태가 세션에 저장되어 재시작 후 마지막 상태로 복원된다(기존 `sidebarCollapsed` 영속)
- [x] 아이콘바 버튼이 현재 표시/숨김 상태를 시각적으로 반영한다(`aria-pressed`)

### US-7.3 분할 패널 비율 조절 — S · 규모 M · ✅ 완료 (※ 실제 드래그는 런타임 스모크 권장)
사용자로서, 작업에 맞게 화면을 배분하기 위해 분할 패널의 비율을 조절하고 싶다.

- [x] 4분할에서 가로·세로 분할선을 각각 드래그해 행·열 비율을 조절한다(grid 2축 독립)

### US-7.4 우클릭으로 현재 폴더에서 터미널 열기 — S · 규모 S · ✅ 완료 (※ 네이티브 `wt.exe` 실행은 런타임 스모크 권장)

- [x] 디렉토리 항목 위 우클릭 메뉴에 "터미널 열기"가 있고, 선택하면 그 폴더를 작업 디렉토리로 터미널이 열린다(`contextMenu.ts`·`openTerminalAt`)

- [x] 주소 표시줄을 단일 클릭하면 편집 모드로 전환되고 전체 경로 텍스트가 입력란에 채워진다(`PanelToolbar.tsx`·`closest('button')` 가드)
- [x] 기존 `Ctrl+L`·더블클릭으로도 동일하게 편집 모드에 진입한다
- [x] Enter로 입력 경로로 이동하고, Esc로 편집을 취소해 원래 표시로 복귀한다
- [x] 잘못된/존재하지 않는 경로는 인라인 오류로 안내되고 이동하지 않으며 편집 모드가 유지된다(`validateAndNavigate` 재사용)
- [x] 클립보드 경로를 붙여넣어 Enter로 즉시 이동할 수 있다
- [x] 입력은 활성 패널 경로만 변경한다(다른 패널·탭에 영향 없음)
- [x] **(2026-06-09 추가·refinement) 원격(SFTP/FTP·M3) 패널에서는 호스트(`sftp://host`)가 고정 프리픽스로 표시되고 경로만(`/mnt/sub`) 입력하면 현재 호스트와 결합해 이동한다**(전체 URI 입력 강요 없음·방어적으로 전체 URI 입력도 처리·로컬 패널 경로 입력 동작 불변·H5×M3 교차·`verify:remote-route` 47). ※ 실 GUI(원격 주소 경로-only 입력·이동) 런타임 스모크 권장 🟡

- [x] 아이콘을 해석할 수 없는 형식·조회 실패 시 일반 파일 아이콘으로 폴백된다(빈칸/깨진 이미지 없음·실패 비캐싱)

## 에픽 10. 되돌리기 · 휴지통 관리 · 유형별 비중 (2026-06-07 편입)

> roadmap §0.5 "P6 미구현 잔여 🔜"의 Should 잔여 3건을 정식 편입한 에픽이다. 모두 **S(Should)·✅ 구현 완료**(team-dev 구현·QA PASS).
> 상세 규칙은 [features §K](./features.md). 단축키는 [PRD 8장](./PRD.md#8-단축키-체계-확정--충돌-없음)(`Ctrl+Z`=되돌리기). 범례: ✅ 완료 · 🟡 부분 · 🔜 미착수.
> US-10.1·10.2는 기존 P6 잔여(되돌리기·휴지통 관리 화면)의 정식 구현, US-10.3은 US-8.1 "(가능 시) 유형별 비중" 선택항의 정식화·구현이다.

### US-10.1 파일 작업 되돌리기 — S · 규모 M · ✅ 완료
사용자로서, 파일 작업 실수를 빠르게 되돌리기 위해 `Ctrl+Z`로 직전 작업을 다단계로 취소하고 싶다.
- [x] `Ctrl+Z`(또는 메뉴/아이콘바 "되돌리기")로 직전 파일 작업이 역연산되어 원상복구된다(`notYet`가 `performUndo()`로 대체됨)
- [x] **다단계 undo 스택**으로 `Ctrl+Z`를 연속 입력하면 여러 작업을 차례로 거슬러 되돌린다(`UNDO_STACK_CAP=50` 상한, 초과 시 오래된 항목 폐기)
- [x] 이름변경(rename↔rename)·새 폴더/파일(→휴지통)·이동(원위치 역move)·복사/붙여넣기(사본→휴지통)가 각 역연산으로 되돌려진다
- [x] 삭제(휴지통)는 **휴지통에서 원래 위치로 복원**되어 되돌려진다(`trashApi.restore` — US-10.2 복원 로직 재사용)
- [x] **영구 삭제(`Shift+Delete`)는 되돌릴 수 없으며**(undo 스택 미push) 시도 시 안내 토스트가 표시된다(임의 복구 시도 없음)
- [x] undo 역연산 위치에 동명 파일/폴더가 새로 생긴 경우 **임의 덮어쓰기 없이 중단·안내**된다(충돌 선검증·US-2.4). ※ copy-undo 보수적(사본 경로 충돌 시 미생성 중단)
- [x] 다중 선택 일괄 작업은 1 undo 단위로 묶여 한 번에 되돌려지고 부분 실패 시 성공/실패가 요약된다
- [x] redo는 본 버전 범위 밖(후속)이며, 되돌릴 작업이 없으면 빈 스택 안내 토스트가 표시된다

### US-10.2 휴지통 관리(복원·비우기) — S · 규모 M · ✅ 완료
사용자로서, 삭제한 파일을 관리하기 위해 휴지통 항목을 보고 원위치로 복원하거나 전체 비우고 싶다.
- [x] 사이드바 "휴지통" 또는 아이콘바 버튼으로 휴지통 관리 화면/모달이 열리고 닫기(`Esc`·닫기 버튼)로 복귀한다(focus trap)
- [x] 휴지통 항목이 **이름·원래 경로·삭제일·크기** 필드로 목록 표시된다(`trash:list`)
- [x] 선택 항목을 **원래 위치로 복원**할 수 있다(`trash:restore`, US-10.1 휴지통 복원도 이 로직 재사용)
- [x] 복원 위치 충돌·예외는 **임의 덮어쓰기 없이** 처리·사유 안내된다(US-2.4)
- [x] **전체 비우기**는 **확인 모달**(되돌릴 수 없음 경고)을 거친 뒤에만 영구삭제한다(`trash:empty` `confirmed=true` 게이트·확인 없이 비우지 않음)
- [x] 복원/비우기는 **검증된 휴지통 항목에만 작용**하고(`$Recycle.Bin` 화이트리스트·sender 검증) 임의 경로 주입 실행 표면을 추가하지 않는다(ADR-005)
- [x] 항목이 이미 사라졌거나 권한 부족 시 사유 안내로 앱이 중단되지 않는다(throw 0·Move-Item 폴백)
- [x] 복원·비우기 후 휴지통 목록이 갱신된다(원위치 패널은 워처 J2 연계 시)

### US-10.3 파일 유형별 비중 인사이트 — S · 규모 S · ✅ 완료
파워유저로서, 무슨 종류가 용량을 차지하는지 파악하기 위해 대시보드에서 확장자 카테고리별 용량 비중을 보고 싶다.
- [x] I1 Top10 스캔 결과에 **확장자 카테고리별(이미지·동영상·문서·코드·압축·기타) 용량 집계**가 함께 산출된다(동일 스캔 1회 byCategory 1패스·추가 I/O 0)
- [x] 대시보드에 카테고리별 **용량 비중(%)·절대 용량·파일 수**가 **차트 + 표**로 표시된다(recharts 재사용·표 병행·바이트 내림차순)
- [x] 확장자는 소문자 정규화 후 카테고리 매핑되며, 매핑에 없거나 확장자 없는 파일은 "기타"로 집계된다(`categorize.ts`)
- [x] 유형별 비중 집계는 I1 스캔의 비차단·진행률·취소·권한 거부 건너뛰기·링크 순환 차단 규칙을 그대로 따른다
- [x] 스캔 대상이 비었거나 전부 접근 불가면 "유형별 데이터 없음"이 안내된다(빈 차트 대신)
- [x] 신규 차트 라이브러리 의존성을 추가하지 않는다(기존 recharts·lazy 청크 재사용)
