## 판정: **FAIL** (반영 후 재검증 필요)

전체 구조(P0 골격 → P1 IPC 계약 동결 → 단일패널 → 탭/분할 → 파일작업 → 검색/세션 → Should → 안정화)는
설계와 임계경로 논리가 견고하고, 단계 순서·병렬화 전략·DoD 측정가능성·스파이크 배치 대부분이 타당하다.
그러나 **PRD Must 기능 2건(B6 파일 실행/열기, E6 설정 + 숨김/확장자 표시)이 어느 단계의 DoD·추적성에도
명시되지 않아 MVP 경계(P0~P5)에서 누락**되었다. 이는 "MVP = Must 전체" 원칙(로드맵 §0, PRD §6) 위반이다.
또한 IPC 계약 동결 범위가 P1 산출물 목록과 일부 모순된다. High 2건 + Med 3건을 반영해야 PASS로 전환 가능하다.

## 반영 항목

### [R-1] B6 "파일 실행/열기"(Must)가 어느 단계 DoD·추적성에도 없음 — 심각도: **High**

- **무엇이**: features §B6(M) — 더블클릭으로 파일 OS 연결 프로그램 실행, `Enter`=열기,
  컨텍스트 메뉴(속성=OS 속성창 호출). traceability §1에 `shell:open`/`shell:show-properties`로
  Must 매핑되어 있고, 시스템 아키텍처 §3.2에 `shell:open`이 정의되어 있다.
- **위치**: 로드맵 P2(단일 패널)는 "폴더 진입"만, P4 산출물에 `shell.handlers.ts(shell:open)`가
  한 줄 있을 뿐, **P4 DoD에 파일 실행/Enter/속성창 검증 항목이 전혀 없다**. 어느 단계 추적성에도 B6 없음.
- **왜 문제**: Must 기능인데 완료 기준이 없으면 "구현됐는지" 게이트로 검증할 수 없다.
  더블클릭=파일 실행은 파일탐색기의 기본 동작이라 MVP에서 빠지면 제품이 성립하지 않는다.
  또한 `shell:open`은 RCE 인접 표면(SA §3.3-4, ADR-005)이라 보안 검증 항목이 반드시 필요하다.
- **어떻게**:
  - P2 또는 P4 중 한 곳에 명시 배정. 권고: **P2**에 폴더 진입과 함께 파일 실행(`shell:open`)·`Enter`=열기를
    넣되, `shell:*` 계약은 P1에서 동결. 속성창/연결프로그램선택(S)은 P4 또는 P6.
  - 해당 단계 DoD에 추가: "더블클릭/`Enter`로 파일이 OS 연결 프로그램으로 실행, 폴더는 진입",
    "`shell:open` 경로 정규화·존재·권한 확인 후에만 위임(미존재/권한밖은 FileOpError, 임의 경로 실행 차단)".
  - 추적성에 `B6 / shell:open / shell:show-properties / ADR-005` 추가.

### [R-2] E6 설정(Must 최소) + 숨김/확장자 표시 토글(F장 Must)이 누락 — 심각도: **High**

- **무엇이**: features §E6(M 최소) — 설정 화면(테마·기본 시작 위치·숨김/확장자 표시·최근 개수·단축키 보기).
  features §F — 숨김/시스템 파일 표시 토글(M), 확장자 표시 토글(M). traceability §1에 feat-E6가
  `settings:get/set`로 Must 매핑되어 있다.
- **위치**: P5 산출물에 `settings:get/set` **핸들러**만 있고, **설정 UI·숨김파일 토글·확장자 표시 토글이
  산출물·DoD·추적성 어디에도 없다**. P1의 `fs:list(showHidden)` 파라미터를 사용자가 제어하는 경로가 로드맵에 전무.
- **왜 문제**: 숨김 파일 표시는 개발자 페르소나(P2 "코드짜는 지현")의 명시 니즈(PRD §4)이자 Must.
  설정 핸들러만 있고 이를 노출하는 UI가 없으면 사용자가 테마 외 설정을 바꿀 수 없다.
  "단축키 목록을 설정/도움말에서 표시"(P3 DoD)도 설정 화면을 전제하는데 그 화면이 어느 단계에도 없다.
- **어떻게**:
  - P5 산출물에 `ui/settings/`(설정 화면) 추가, panelsSlice/uiSlice에 showHidden·showExtensions 상태 추가.
  - P5 DoD에 추가: "설정 화면에서 테마·기본 시작 위치·숨김 파일 표시·확장자 표시·최근 개수를 변경하고
    settings.json에 영속", "숨김/확장자 표시 토글이 패널 목록에 즉시 반영(`fs:list` showHidden 연동)".
  - 추적성에 `feat-E6 / settings:get/set`, `F장 숨김·확장자 토글` 추가.
  - (참고) P3 DoD "단축키 목록을 설정/도움말에서 표시"가 P5 설정 화면에 의존하므로,
    설정 화면 최소 골격 시점을 P3와 정합되게 명시(또는 P3에서는 임시 도움말 패널로 분리 명시).

### [R-3] IPC 계약 동결 범위가 P1 산출물 목록과 불일치 — 심각도: **Med**

- **무엇이**: 로드맵 §0·§4 병렬화 규칙은 "P1에서 `shared/ipc`·`shared/dto` **전체** 계약 동결이 모든
  병렬 작업의 선행 조건"이라고 선언한다. P4 의존 칸도 "계약(`op:*`·`fs:mkdir/rename`)은 P1에서 합의"라 한다.
- **위치**: 그러나 P1 **산출물 목록**에는 `fs:*` 읽기 계열 채널·DTO만 열거되고, `op:*`·`shell:*`·
  `clipboard:*`·`session:*`·`settings:*`·`workspace:*` 채널/타입의 **계약 정의(contracts.ts에 들어갈 타입)**가
  명시되지 않는다. 실제 채널 핸들러는 P4/P5/P6에서 처음 등장.
- **왜 문제**: "계약을 P1에서 동결 → 이후 병렬"이라는 핵심 전략이 성립하려면 P1 산출물에
  **전 채널의 타입 계약**이 들어가야 한다. 핸들러 구현은 나중이어도 타입(요청/응답/이벤트 shape)은
  P1에 있어야 frontend가 모킹 위에서 P4/P5 UI를 병렬 선행할 수 있다. 현재 서술은 P1 산출물(타입)과
  병렬화 전제가 어긋나 혼선 소지.
- **어떻게**: P1 산출물에 명시 구분 — "(a) **전 채널의 타입 계약**(`op:*`/`shell:*`/`clipboard:*`/
  `session:*`/`settings:*`/`workspace:*` 포함)을 contracts.ts에 동결, (b) **핸들러 구현은
  fs:* 읽기 계열만 P1, 나머지는 해당 Phase**". DoD에 "contracts.ts에 전 채널 타입 존재, 미구현
  핸들러는 명시 stub/주석으로 계약만 고정" 추가.

### [R-4] P5 의존성 표기가 본문과 임계경로에서 미묘하게 다름 — 심각도: **Low**

- **무엇이/위치**: §1 요약표 P5 의존 = "P3, P4". §3 P5 의존 = "P3(탭/레이아웃 스냅샷), P4(작업 후 상태).
  검색/필터·테마·상태바는 P2 위에서도 일부 선행 가능". §2 임계경로 주석도 "세션복원은 P3·P4 완료가 전제".
- **왜 문제는 아닌 수준이나**: 세션복원만 P3·P4에 강하게 의존하고 검색/테마/상태바는 P2 의존이다.
  현재 표기상 P5 전체가 P4(파일작업) 완료를 기다리는 것처럼 보여, 병렬 착수 가능한 P5 하위작업
  (검색/테마/상태바)이 불필요하게 직렬화될 오해 소지.
- **어떻게**: P5를 두 트랙으로 쪼개 표기 권고 — "P5a(검색/필터·테마·상태바: 의존 P2) / P5b(세션복원·
  즐겨찾기 영속: 의존 P3·P4)". 또는 요약표 의존 칸에 "P3·P4(세션복원 한정), 그 외 P2"로 주석.

### [R-5] US-1.3 "드롭 가능 대상 하이라이트" 등 일부 수용기준의 DoD 누락 — 심각도: **Low**

- **무엇이/위치**: US-1.3 수용기준 "드롭 가능한 대상이 하이라이트된다", "드래그 중 의도가 커서·툴팁 표시"는
  설계 SW §8에 "시각 피드백=UI"로 있으나, P4 DoD의 D&D 항목은 의도판정·드롭위치·차단 위주이고
  **하이라이트/커서·툴팁 피드백을 명시 검증하지 않는다**.
- **왜 문제**: 사용자 오작동 방지 핵심(features §A3 주석)인데 DoD에 없으면 누락 위험.
- **어떻게**: P4 DoD D&D 항목에 "드롭 가능 대상 하이라이트 + 복사/이동 커서·툴팁으로 의도 상시 표시" 추가.

## 확인 필요 (사용자/PM 판단)

- **B6 파일 실행을 P2에 넣을지 P4에 넣을지**(R-1): 권고는 P2(기본 탐색 동작)이나, `shell:*` 보안 검증을
  파일작업과 함께 P4에서 묶는 선택지도 합리적. 단계 배정은 PM/tech-lead 결정 사안.
- 위 R-1·R-2는 **MVP 범위(Must) 누락**이라 출시 범위에 직접 영향. 반영 전 진행 시 MVP 미완성 리스크.

## 재검증 기준

R-1·R-2(High) 두 건이 단계 DoD·산출물·추적성에 반영되고, R-3(계약 동결 범위)이 P1 산출물에 명시되면
PASS 전환 가능. R-4·R-5는 반영 권고하되 게이트 차단 사유는 아니다.
