# 기획 산출물 독립 검증 보고 — Explorer (멀티 디렉토리 파일탐색기)

> 검증일: 2026-06-06 · 검증: 독립 검증 담당(Reviewer) · 회차: 1
> 대상: `docs/PRD.md`, `docs/features.md`, `docs/user-stories.md`, `docs/flows.md`

---

## 판정: **FAIL**

전반적으로 완성도가 높고 핵심 차별점(탭 + 분할 패널 + 패널 간 이동/복사)의 추적성도 대체로 양호하다.
그러나 **단축키 충돌(F6 이중 할당, F5 충돌의 불완전한 처리)**, **수용 기준의 검증 불가능한 표현**,
**일부 핵심 기능의 추적성 누락**, **MoSCoW 표기 비일관** 등 **출시 전 반드시 정리해야 할 결함**이 있어 FAIL로 판정한다.
High 항목을 반영하면 재검증 시 PASS 가능한 수준이다.

---

## 항목별 평가

### 1. 완료 기준 충족 (4개 문서 존재·내용) — PASS
- PRD / features / user-stories / flows 4개 문서 모두 존재하고 내용이 충실하다.
- 문서 간 상호 링크가 걸려 있어 탐색성도 좋다.

### 2. 범위 명확성 (MVP 경계·MoSCoW 일관) — **부분 FAIL**
- "MVP = Must 전체" 정의가 명확하고 Won't 항목까지 명시되어 좋다.
- 그러나 **세션 복원(US-5.5)의 우선순위 표기가 문서마다 흔들린다**: PRD는 "비정상 종료 후 세션 복원"을 Must 비기능요구로, user-stories 백로그표는 `M/S` 혼합으로 표기. (M2 참조)
- **미리보기 패널**이 features에서는 D3(S)인데 user-stories US-4.3은 S, PRD Should — 여기는 일관. 단, flows 4장에서 "미리보기 패널(S)"로 표기는 일관하나 IA 다이어그램(1장)에는 미리보기 영역이 빠져 있어 독자가 구조를 그릴 수 없다. (M5 참조)

### 3. 추적성 (핵심 기능 PRD→features→user-stories) — **부분 FAIL**
- 핵심 3종(탭 US-1.1 / 2분할 US-1.2 / 패널 간 이동·복사 US-1.3)은 PRD→features(A1/A2/A3)→user-stories까지 끊김 없이 연결됨. 양호.
- 그러나 **PRD Must에 명시된 일부 기능이 user-stories에 수용 기준으로 내려오지 않았다**:
  - **"탭 복제"**(features A1)와 **"닫은 탭 복원"**은 US-1.1에 복원만 있고 복제는 누락.
  - **충돌 처리(features D4)**가 독립 스토리 없이 US-2.3 수용기준 한 줄로만 존재. 충돌은 핵심 데이터안전 기능인데 "둘 다 유지/모두 적용/폴더 병합/읽기전용 대상" 수용기준이 빠짐. (H3 참조)
  - **상태바(features E5 / PRD Must)**가 독립 스토리 없음(US-5.1·US-4.2 수용기준에 단편적으로만 등장). 추적성 단절. (M3 참조)

### 4. 수용 기준의 검증 가능성 — **부분 FAIL**
- 대부분 테스트 가능하게 작성됨(키 입력·상태 변화 명시).
- 그러나 **검증 불가능한 정성 표현이 잔존**:
  - US-1.3 "빠르게 옮기기 위해" — 목적 문구라 허용되나, 본문 곳곳 "즉시/점증/빠른"이 측정 기준 없이 수용기준화됨.
  - US-4.1 "즉시(점증) 목록이 필터링된다" — "즉시"의 기준(예: 입력 후 N ms 내 반영) 없음. (H4 참조)
  - PRD 성능 지표는 정량적이나(1.5초/200ms), 이 수치가 **어떤 수용 기준에도 연결되지 않음** — US-5.2에 진행률 갱신 지연(200ms) 기준이 빠짐. (H4 참조)

### 5. 일관성 (화면 구조·용어) — **부분 FAIL**
- 탭/패널/사이드바/주소창/상태바 5요소 정의가 PRD·features·flows에서 대체로 일치.
- **용어 흔들림**: "주소 표시줄"(PRD/features) vs "주소창"(user-stories/flows) vs "미니주소"(flows IA). 동일 대상이면 통일 필요. "분할 패널" vs "다중 페인" vs "패널 영역" 혼용. (M4 참조)
- **IA 다이어그램과 기능 정의 불일치**: flows 1장 IA에는 미리보기 패널·진행률 다이얼로그 위치가 없음. (M5 참조)

### 6. 엣지/예외 처리 — PASS (경미한 보완 권고)
- 충돌(같은 이름), 권한 오류, 대용량 취소, 같은/다른 드라이브 규칙, 롱패스, 심볼릭링크, 네트워크 끊김, 사용 중 파일 등 핵심 예외가 features F장·flows 3장에 잘 정리됨. 우수.
- 보완 권고(Low): **드래그&드롭으로 같은 폴더(자기 자신)에 드롭**, **부모 폴더를 자식으로 이동(순환)** 시 동작 미정의. (L1 참조)

### 7. 구현 가능성 / 리스크 / 미해결 질문 — **부분 FAIL**
- 리스크(R1~R3)와 미해결 질문(Q1~Q4)이 의사결정 가능한 형태로 제안값까지 포함됨. 좋다.
- 그러나 **과업 지시문이 말한 "planner가 남긴 5개 미해결 질문"과 실제 문서가 불일치**: PRD에는 Q1~Q4(4개), flows에는 별도 디자인 질문 4개. 5개라는 합의된 단일 목록이 없다. 미해결 질문이 PRD와 flows에 분산되어 추적이 어렵다. (M6 참조)
- **F5/F6 단축키 충돌이 "미해결 질문"으로만 미뤄졌는데, 그중 F6 충돌은 인지조차 안 됨** — 아래 H1은 단순 미해결이 아니라 명세 내부 모순이다.

## 반영(수정) 항목 목록

### [H1] F6 단축키 이중 할당 — 명세 내부 모순 · 심각도 High
- **무엇이**: `F6`가 (a) "패널 포커스 이동"과 (b) "다른 패널로 이동(파일 이동 작업)" 양쪽에 동시 할당됨.
- **어느 문서**: `features.md` 36행(패널 전환=F6) vs 52·172행(패널작업 이동=F6); `user-stories.md` 25행(포커스 이동=F6) vs 37행(이동 작업=F6).
- **왜 문제**: 동일 컨텍스트(분할 패널 활성 상태)에서 한 키가 두 동작에 매핑되어 결정적 충돌. planner는 178행에서 **F5 충돌만** 미해결 질문으로 적었고 F6 충돌은 인지하지 못함. 이건 미해결 질문이 아니라 명세 자체의 모순이라 설계로 넘기면 안 됨.
- **어떻게**: 포커스 이동과 파일 이동 작업 키를 분리. 예) 포커스 이동은 `F6`/`Ctrl+←→`로 통일, 패널 간 복사/이동은 `F5`(복사)/`F8` 등 비충돌 키로 재배정하고 4개 문서 일괄 수정. 미해결 질문 항목도 "F5/F6 양쪽 충돌"로 갱신.

### [H2] F5 충돌(새로고침 vs 패널 간 복사) 방치 — 심각도 High
- **무엇이**: `F5`가 "새로고침"(features 176행)과 "다른 패널로 복사"(52·172행)에 동시 할당. 미해결 질문으로만 표기되고 MVP 단축키 표에 충돌 상태 그대로 노출됨.
- **어느 문서**: `features.md` 52·172·176·178행, `flows.md` 111행, `user-stories.md` 37행.
- **왜 문제**: MVP 단축키 체계(E1, Must)인데 핵심 키가 미확정 상태로 user-stories 수용기준(US-1.3 37행)에 이미 `F5 복사`로 박혀 있음. 수용기준이 미확정 명세를 참조하는 역전 구조.
- **어떻게**: H1과 함께 단축키 충돌을 기획 단계에서 1차 확정(설계로 미루지 말 것). 최소한 user-stories 수용기준에서는 미확정 키를 빼거나 확정 키로 교체.

### [H3] 충돌 처리(데이터 안전 핵심)의 수용 기준 누락 — 심각도 High
- **무엇이**: 충돌 처리(덮어쓰기/건너뛰기/둘 다 유지/모두 적용/폴더 병합/읽기전용·사용중 대상)가 features D4에 규칙은 있으나, user-stories에는 US-2.3의 수용기준 한 줄("충돌 시 덮어쓰기/건너뛰기/둘 다 유지 선택이 제공된다")뿐.
- **어느 문서**: `features.md` 148~158행 vs `user-stories.md` 70행.
- **왜 문제**: 제품 원칙 3("안전한 파괴적 작업")의 핵심인데 수용기준이 빈약. "폴더 병합", "모두 적용 일괄", "권한 없는 대상 건너뜀+실패 목록"이 테스트 케이스로 명세화되지 않음. QA가 검증 기준을 못 만듦.
- **어떻게**: 충돌 처리를 독립 스토리(예: US-2.4 "복사/이동 충돌 해결")로 승격하고, D4 표의 각 옵션·폴더 병합·읽기전용/사용중 대상 처리를 수용기준 체크리스트로 전개.

### [H4] 성능·반응성 정량 기준이 수용 기준에 미연결 — 심각도 High
- **무엇이**: PRD 성능 목표(10,000개 1.5초, 진행률 200ms 갱신)가 어떤 user-story 수용기준에도 연결되지 않음. 반대로 US-4.1 "즉시 필터링" 등은 측정 기준이 없음.
- **어느 문서**: `PRD.md` 39~40·121~123행 vs `user-stories.md` US-5.2(131~136행)·US-4.1(102~107행).
- **왜 문제**: 정량 목표가 PRD에만 떠 있어 "검증 가능성" 요건 미충족. US-5.2 진행률 수용기준에 200ms 갱신이 없고, US-4.1 "즉시"는 비측정 표현.
- **어떻게**: US-5.2에 "진행률 표시가 200ms 이내 갱신된다", "10,000개 폴더 첫 화면이 1.5초 이내 렌더된다"(별도 성능 스토리 또는 US-2.1에) 수용기준 추가. "즉시/점증"은 "입력 후 X ms 내 목록 반영" 등 측정 가능 표현으로 교체.

### [M1] 세션 복원 우선순위 표기 비일관 — 심각도 Med
- **무엇이**: US-5.5가 백로그표에서 `M/S` 혼합 표기(177행). 자동 복원=M, 명시 저장=S로 분해되어 있으나 단일 ID에 두 우선순위가 섞여 백로그 집계·계획 시 혼란.
- **어느 문서**: `user-stories.md` 148·177행, `PRD.md` 166행(Q3).
- **왜 문제**: 한 스토리 ID에 M과 S가 공존하면 MVP 범위 산정이 모호.
- **어떻게**: US-5.5(자동 복원, M)와 US-5.6(워크스페이스 명시 저장, S)로 분리하고 백로그표에 각각 행 추가.

### [M2] "탭 복제" 기능 추적성 단절 — 심각도 Med
- **무엇이**: features A1에 "탭 복제"(20행)가 있으나 PRD Must 목록·user-stories US-1.1 어디에도 없음.
- **어느 문서**: `features.md` 20행 vs `PRD.md` 79~93행 · `user-stories.md` US-1.1.
- **왜 문제**: features에만 존재 → MVP 포함 여부 불명, 수용기준 없음.
- **어떻게**: 탭 복제를 PRD Must(또는 Should로 명시)와 US-1.1 수용기준에 반영하거나, MVP 제외면 features에서 우선순위(S/C) 표기.

### [M3] 상태바 독립 스토리 부재 — 심각도 Med
- **무엇이**: 상태바(features E5, PRD Must, flows IA)가 user-stories에 독립 스토리 없이 US-5.1/US-4.2 수용기준 단편으로만 존재.
- **어느 문서**: `features.md` 194~195행 · `PRD.md` 93행 vs `user-stories.md`.
- **왜 문제**: Must 기능인데 추적 가능한 스토리·완료기준 부재.
- **어떻게**: US-5.x로 상태바 스토리 신설(항목 수/선택 개수/용량/활성 패널 경로 표시 수용기준).

### [M4] 용어 비일관 — 심각도 Med
- **무엇이**: "주소 표시줄/주소창/미니주소", "분할 패널/다중 페인/패널 영역" 등 동일 대상에 복수 용어 혼용.
- **어느 문서**: 전 문서(`PRD`·`features`·`user-stories`·`flows`).
- **왜 문제**: 설계·개발 단계에서 동일 컴포넌트를 다른 것으로 오인할 위험.
- **어떻게**: 용어 사전(1개 표준어로 통일) 추가 후 4개 문서 일괄 정정. 예: 주소 표시줄, 분할 패널, 패널.

### [M5] IA 다이어그램과 기능 정의 불일치 — 심각도 Med
- **무엇이**: flows 1장 IA 메인 화면에 미리보기 패널·진행률 다이얼로그 위치가 표현되지 않음(4장 텍스트로만 언급).
- **어느 문서**: `flows.md` 10~27행 vs 99~104행, `features.md` D3·E4.
- **왜 문제**: IA가 화면 전체 구조의 단일 출처인데 주요 영역이 누락되어 구조 인지 불가.
- **어떻게**: IA 다이어그램에 미리보기 패널(S, 우측/하단 토글)·진행률 인디케이터(상태바/다이얼로그) 위치 주석 추가.

### [M6] 미해결 질문이 분산·"5개" 불일치 — 심각도 Med
- **무엇이**: 과업은 "planner가 남긴 5개 미해결 질문"을 전제하나, PRD에는 Q1~Q4(4개)+R2 규칙, flows에는 별도 디자인 질문 4개로 흩어져 단일 5개 목록이 없음.
- **어느 문서**: `PRD.md` 157~168행, `flows.md` 108~113행.
- **왜 문제**: 의사결정 추적이 어렵고, 단축키 충돌(H1/H2)처럼 일부는 "질문"이 아니라 "결함"이 섞여 있음.
- **어떻게**: 미해결 질문을 한 곳(PRD 9장)에 통합한 단일 번호 목록으로 정리하고, 각 항목에 결정자·기한·기본 제안값 명시. 명세 모순(F6/F5)은 질문에서 빼고 결함으로 분류해 즉시 확정.

### [L1] 드래그&드롭 자기참조/순환 케이스 미정의 — 심각도 Low
- **무엇이**: 같은 폴더(자기 자신)로 드롭, 부모 폴더를 그 자식으로 이동(순환) 시 동작 미정의.
- **어느 문서**: `features.md` A3·F장, `flows.md` F1.
- **왜 문제**: 흔한 사용자 실수 경로인데 차단/무시 규칙 없음.
- **어떻게**: features F장 또는 A3에 "동일 위치 드롭=무시", "조상→자손 이동=차단 및 안내" 규칙 추가.
