## 세부 확인 (요청 1~5)

### 1. R-1·R-2 산출물·DoD·추적성·보안검증
- **B6 실행(P2)**: DoD가 진리표(폴더=진입/파일=실행)와 **보안 검증**(경로 정규화·`..` 차단·존재·권한 3관문 통과한 경로만 `shell.openPath` 위임, 실패 시 실행 없이 FileOpError)을 측정 가능하게 명시. QA 포인트에 "미존재/`..` 이탈/권한밖 경로 주입 시 실행 차단 실측" 포함. ADR-005 추적성 연결. → 1차 R-1 권고(보안 DoD 포함) 충족.
- **B6 속성창(P4)**: `shell:show-properties` 산출물·DoD·추적성 모두 존재. `shell:open-with`(연결 프로그램 선택)는 features의 Should 표기에 맞춰 P6로 정확히 분리(L155).
- **E6+토글(P5a)**: 숨김 토글이 `fs:list(showHidden)` 사용자 제어 경로까지 연결(1차 R-2 핵심 지적 "설정 핸들러만 있고 노출 UI 없음" 해소). 설정 단축키 섹션이 P3 DoD의 실제 호스트로 명시되어 P3↔P5 의존이 정합(아래 4 참조).

### 2. R-3 P1 계약 동결 / 병렬화 모순
- P1 산출물·DoD·병렬화 규칙·게이트(L209 "전 채널 타입 동결")가 모두 "타입 전 채널 동결 / 핸들러는 Phase별"로 일관 서술. frontend가 모킹 위에서 P2/P4/P5 UI 병렬 선행 가능하다는 전제와 산출물(타입)이 더 이상 어긋나지 않음. DoD에 "frontend가 미구현 채널을 모킹 호출해도 타입 일치(병렬 선행 가능성 검증)" 추가되어 검증 가능.

### 3. R-4·R-5
- R-4: P5a(의존 P2)/P5b(의존 P3·P4) 4개 위치 모두 일관. 검색/테마/상태바/설정의 불필요한 직렬화 오해 제거.
- R-5: P4 DoD·QA·추적성에 시각 피드백 반영. user-stories.md 수용기준과 1:1.

### 4. 새 모순 점검 — 없음
- **P3↔P5a 의존 역전 우려**: P3 DoD가 단축키 "표시"를 P5a 설정 화면에 위임하나, P3는 "레지스트리 노출 API까지만"으로 책임을 축소하고(L114), 실제 표시 호스트는 P5a로 이관(L144)했다. P3 완료가 P5a를 선결로 요구하지 않으므로 의존 역전 아님(임계경로 P2→P3→P4→P5 유지). 합리적 처리.
- **역할분담표(§4)**: P2 backend `shell:open`, P4 backend `shell:show-properties`, P5 frontend P5a/P5b 분리, P4 frontend 하이라이트/커서 피드백 — 본문 상세와 표가 일치.
- **임계경로**: P5a가 P2 위 선행 가능으로 표기되나 MVP 임계경로 사슬(P0→…→P5)은 불변. 모순 없음.
- 추적성 표(traceability.md)와 로드맵 추적성 칸의 채널 매핑(B6=shell:*, E6=settings:get/set) 상호 일치.

### 5. 종합 — MVP=Must 전체 / 착수 가능성
- PRD §6 Must 기능(탐색·실행·CRUD·휴지통·검색·필터·설정·숨김/확장자·세션복원·테마·상태바·탭/2분할·단축키)이 P0~P5 DoD에 빠짐없이 게이트로 묶임. Should(4분할·미리보기·워크스페이스·텔레메트리·open-with)는 P6로 정확히 분리.
- 각 Phase가 측정 가능한 DoD·QA 포인트·추적성·담당을 갖춰 세부 계획 착수 가능. 스파이크(SPK-Worker P4 선결·SPK-Perf P5 선결)·게이트 루프(§5)도 유지.
