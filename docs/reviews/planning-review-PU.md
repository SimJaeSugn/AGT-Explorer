## 요약
기능 설계·수용 기준·MVP 경계·보안 반영·마일스톤 의존성은 전반적으로 견고하고, **PRD §6·user-stories·flows·백로그표 4종은 번호(US-15.1~US-20.3)·MoSCoW·상태(전부 🔜)가 서로 정합**한다. 그러나 **features.md §R~§U의 각 절 "목적" 줄에 박힌 US 참조 번호가 전부 한 챕터씩(또는 그 이상) 어긋나 있다(추적성 깨짐)**. 이는 추적성 무결성을 직접 훼손하는 결함이라 그대로 진행 불가. 그 외 경미한 일관성 흠 2건을 함께 반영 권고한다.

### [반영-1] (치명·추적성) features.md §R~§U 절의 US 참조 번호가 전부 어긋남

  1. 한 문서(features.md) 안에서 동일 기능을 가리키는 추적 ID가 다른 3종 문서(PRD §6 MoSCoW·user-stories 에픽/백로그표·flows F20~F33)와 전부 어긋난다. 예: features §R1은 `US-15.2/US-16.x`라고 적었으나 실제 확정 ID는 `US-17.1`(에픽17). flows F22도 `US-17.1`로 정확하므로, **features.md만 단독으로 틀린 단일 결함**이다.
  2. 특히 **R1(라인 1185)이 가장 심각**하다. 존재하지 않는 ID `US-15.2`를 만들어냈고("US-15.2 → 에픽15 외"), 동시에 "에픽16 R 묶음"이라고 적었는데 R 묶음은 실제로 **에픽17**이다(에픽16은 Q1 압축 단일). 한 문장에 잘못된 ID·잘못된 에픽 두 개가 들어 있다.

- **권고(수정 지시)**:
  - 위 표의 "올바름" 값으로 각 절 목적 줄의 US 참조를 정정한다(각 기능당 1개 US로 1:1 매핑이므로 `US-NN.x` 같은 와일드카드가 아니라 **정확한 단일 ID**로 적을 것: R1=US-17.1, R2=US-17.2, R3=US-17.3, R4=US-17.4, S1=US-18.1, S2=US-18.2, T1=US-19.1, T2=US-19.2, T3=US-19.3, U1=US-20.1, U2=US-20.2, U3=US-20.3).
  - R1 라인 1185는 "US-15.2 → 에픽15 외, 에픽16 R 묶음 — US-16.x" 전체를 "(US-17.1·에픽17)"로 교체한다.
  - 정정 후 PRD §6·user-stories·flows와 4종 전부 동일 ID인지 재확인.

### [반영-2] (경미·일관성) §R 챕터 헤더의 우선순위 인라인 요약과 본문 표기 점검

- **무엇**: features §R 챕터 도입부(라인 1181)는 "R1·R2 = S, R3 = S, R4 = C"로 적었고 각 절 제목·PRD·US와 정합한다. 단, **§R 챕터가 4개 절(R1~R4)을 한 에픽(에픽17)에 묶었는데**, R1의 잘못된 "에픽15/에픽16" 표기([반영-1])가 이 묶음 구조를 흐린다.
- **위치**: features.md 라인 1178~1185.
- **문제**: [반영-1]을 고치면 자동 해소되나, 챕터 도입부에 "이 챕터(§R) 4기능 = 에픽17(US-17.1~17.4)"이라는 매핑 한 줄이 없어 독자가 챕터↔에픽 대응을 즉시 못 잡는다(다른 챕터도 동일하나 §R이 4:1이라 혼동 위험이 가장 큼).
- **권고**: §R~§U 각 챕터 도입부에 "본 챕터 = 에픽NN(US-NN.x)" 한 줄을 추가(또는 [반영-1] 정정만으로 갈음). 최소한 R1의 오기는 반드시 제거.

### [반영-3] (경미·확인) "차이만 보기"의 검색/필터 병행과 T1 태그 필터 상호작용 미정의

- **무엇**: P1 "차이만 보기"(라인 1108)와 T1 "태그 필터"(라인 1332)·T3 "정렬/필터 프리셋"(라인 1370)이 모두 "기존 검색/필터(D1·D2)와 병행"이라 적었으나, **여러 신규 필터(차이만/태그/프리셋)가 동시에 걸릴 때의 합성 규칙(AND/OR·우선순위)** 은 어디에도 없다.
- **위치**: features §P1·§T1·§T3 수용 기준.
- **문제**: 수용 기준이 각각은 측정 가능하나, "병행" 시 결과 합성이 모호 → 구현/QA 단계에서 해석 분기 가능. 다만 신규 14종은 단계가 M6~M9로 분산되고 chief-architect 설계로 정밀화 예정이라 **차단(blocking)은 아님**.
- **권고**: 설계 단계에서 "필터 합성 = AND(모든 활성 필터 동시 만족)" 같은 기본 규칙을 1줄 못 박을 것을 chief-architect에게 인계. 기획 문서에는 "복수 필터 동시 적용 시 AND 합성(상세는 설계)" 정도로 명시 권고.
